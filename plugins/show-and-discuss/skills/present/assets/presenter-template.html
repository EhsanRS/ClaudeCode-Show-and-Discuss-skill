Thanks for joining. I'm going to walk you through the plan for adding dark mode to the Settings page before I write any code. It takes about three minutes. Interrupt me at any point by just talking.
Context

Why this, why now

Users are asking

14 support tickets this quarter mention eye strain or "dark mode". It is the top-voted item on the feedback board.

The groundwork exists

Colours already live in CSS variables since the design-token refactor, so the change is mostly additive.

Low blast radius

Starting with Settings only keeps the change reviewable and lets us learn before rolling out app-wide.

Two reasons this is worth doing now. [[spotlight why-users]] First, users are asking for it — it's the most requested item this quarter. [[spotlight why-tokens]] Second, the design-token refactor already moved our colours into CSS variables, so most of the work is adding a second set of values rather than rewriting components.
How

Approach

No flash of the wrong theme: a 6-line inline script in <head> sets data-theme before first paint.
Here is how it fits together. [[spotlight flow]] The toggle writes the preference through a small hook, [[point store]] usePreference, which saves it locally and syncs it to the user's profile. The value lands on the html element as a data-theme attribute, and the token stylesheet switches values from there. [[spotlight no-flash]] One detail worth calling out: an inline script in the head applies the theme before first paint, so there's no white flash on load.

Delivery

Three slices, each shippable

  1. Dark token values + head scriptAdd dark values to tokens.css; inline script sets data-theme. Behind a flag. Tests: snapshot both themes.
  2. Appearance setting UIThe three-way control and usePreference hook with localStorage. Tests: unit + one e2e toggle test.
  3. Sync to profilePersist the choice via the existing preferences API so it follows the user across devices.
I'd deliver it in three slices, each one shippable on its own. [[point slice-1]] Slice one adds the dark token values and the head script, behind a flag. [[point slice-2]] Slice two is the actual setting with its hook. [[point slice-3]] Slice three syncs the choice to the user's profile. After each slice I'll run the tests and show you the result before moving on.
